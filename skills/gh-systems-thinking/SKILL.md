# gh-系统思维：系统思考

基于德内拉·梅多斯《系统之美》（*Thinking in Systems: A Primer*）的系统思考实践框架。

系统思考不是工具，是换上另一副眼镜看世界——不看事件，看结构。不看责任人，看让行为必然发生的存量-流量-反馈关系。

## 什么时候用

用户给出任何一个"反复出问题"的复杂场景——公司亏损、政策失效、团队内耗、项目延期、环境恶化、个人习惯改不掉——都可以启动这套分析。

核心判断：**如果同一个问题换了人还出现，应该用系统思考。** 人反复犯同一个错，错不在人，在让他"不得不这么干"的结构。

## 系统分析的六步流程

每一步走完再走下一步。六步走完，输出一张完整的"系统诊断书"。

### Step 1：画边界

问用户三个问题来确定分析范围：

1. **谁的什么问题？**——系统是为谁服务的（什么角色），ta 遇到了什么反复出现的困境
2. **边界在哪？**——往上到什么层面（公司/行业/社会/地球），往下到什么层面（部门/个人/动作）
3. **时间跨度多长？**——几天/几个月/几年？反馈延迟的不同尺度让系统行为完全不同

画边界的规矩：宁可切小切准，不要贪大求全。一个小镇的供水系统分析比"全球水资源"有用一万倍。

边界画完，一句话陈述：**"我分析的系统是 X（主体），Y 是它反复出现的问题，我关心的范围是 Z，时间跨度为 T。"**

### Step 2：找存量与流量

存量（stock）是系统里可以积累的量——钱、库存、信任、人口、碳排放、代码行数、团队士气。流量（flow）是让存量变化的速率——收入/支出、入库/出库、信任建立/信任破裂。

画出核心存量和它们的主要流入/流出。用这个模板：

```
[流入量] ——→ [ 存  量 ] ——→ [流出量]
                ↑缓冲↓
              （变化慢）
```

找存量的关键：**存量是系统里不变慢半拍的东西。** 你早上决定要多运动（决策），但体重（存量）不会明天就变。存量给了系统惯性，也让人误判——因为存量没变，就以为干预没效，放弃了。

存量清单列出 2-4 个最重要的。每个标出它现在的水平（高/中/低，或大致数值），以及它的流入和流出各是什么。

### Step 3：找反馈回路

两个方向。

**调节回路（Balancing Loop）——把系统往回拉的力。** 恒温器、饿了下丘脑告诉你吃饭、库存太高降价促销。调节回路让系统趋向目标/稳定。在图上画 "B"。

找到调节回路后必问：**调节回路的目标是什么？** 很多时候系统的灾难不是没有调节回路，是调节回路的目标本身有问题——一个追求"季度利润最大化"的公司，其调节回路会精准地牺牲长期投资来满足短期数字。

**增强回路（Reinforcing Loop）——把系统加速推的力。** 复利、口碑传播、恐慌抛售、贫困陷阱。越多→越多（良性），越少→越少（恶性）。在图上画 "R"。

找反馈回路的铁律：**找不到至少一组调节回路和一组增强回路，说明你没看清系统。** 系统一定同时有这两种力在拉扯——一种维稳，一种变局。只看到一种 = 你只看到了一半。

### Step 4：识别人与延迟

当系统中的人做出决策时，他们依据的是**可得信息**，不是全部信息。Meadows 把这个叫"有限理性"（bounded rationality）——每个人都做对自己当下最合理的决定，合起来却把系统推向了谁都不要的方向。

找"有限理性陷阱"：列出 2-3 个关键角色，每个人知道什么、不知道什么、他做决定时看的是什么指标。然后问：**如果每个人都是理性的，这个系统的糟糕结果是怎么从他们的理性选择中自然产生的？**

然后找延迟（delay）。延迟是系统里最被低估的捣乱者。常见延迟：

- 决策到效果显现的延迟（种树到森林，三年）
- 信息传递的延迟（季度报表，三个月后才看到）
- 反馈感知的延迟（过量捕捞，鱼少了渔民才知道）

找延迟的实用方法：**系统里最让人焦虑的那段时间空档，就是延迟。** "我们已经采取措施了，为什么还没好转？"——这就是延迟在说话。

延迟导致过冲和震荡：你踩刹车（调节回路启动了），但因为延迟，车没马上停，你继续踩，等车停了已经过头了，你又松油门，又过头了。城市交通、经济周期、供应链波动，都是这个结构。

### Step 5：诊断系统陷阱

对照 Meadows 的八大系统陷阱，看当前系统匹配哪几个。匹配就标出，不匹配就不强套。

| 陷阱 | 症状 | 匹配？ |
|------|------|--------|
| **政策阻力** | 不同角色往相反方向拉，系统卡在原地不动 | □ |
| **公地悲剧** | 共享资源被每个人透支，没人停手 | □ |
| **目标侵蚀** | 标准越降越低，"还行"代替"好" | □ |
| **竞争升级** | 双方不断加码，资源全烧在对抗上 | □ |
| **富者愈富** | 赢家通吃，输家出局，马太效应 | □ |
| **转嫁负担** | 短期救济代替长期修复，上瘾了 | □ |
| **规避规则** | 钻规则空子，指标好看但系统坏了 | □ |
| **目标错位** | 系统在优化错误的目标（GDP≠福祉） | □ |

诊断正确的前提：**同一个陷阱描述能套到当前系统的事实上，不是比喻上。** "这不就是公地悲剧吗" 要能说出：共享资源是什么、谁在使用、为什么每个人多取一点对自己合算但对全体有害。

### Step 6：找杠杆点——在哪干预

Meadows 的 12 层杠杆点排序，从低（易做但没用）到高（难做但有用）。逐层排查当前系统有哪些可以动的杠杆：

| 层次 | 杠杆 | 当前系统可能的机会 |
|------|------|-------------------|
| 12 | 改变数字/参数（调价、加预算） | □（效力低，但最容易下手） |
| 11 | 改变缓冲器（加大/减小存量） | □ |
| 10 | 改变存量-流量结构（重建物理系统） | □ |
| 9 | 改变延迟（加快/减慢反馈速度） | □ |
| 8 | 改变调节回路（增强/减弱稳定力） | □ |
| 7 | 改变增强回路（放缓增长/阻止崩溃） | □ |
| 6 | 改变信息流（恢复缺失的信息） | □ |
| 5 | 改变规则（激励、惩罚、约束） | □ |
| 4 | 增强自组织能力（鼓励多样性和实验） | □ |
| 3 | 改变系统目标（重新定义"成功"） | □ |
| 2 | 改变社会范式（底层心智模型） | □ |
| 1 | 超越范式（没有范式是真理） | □ |

**锁定 1-2 个最高且可行的杠杆。** 不是让你从第 12 层做起——你知道该改规则（第 5 层）但暂时推不动，那就从信息流（第 6 层）切入作为突破口。关键在于选一个**既在高层又推得动**的。

## 输出格式

分析完成后，用 markdown 输出一份**系统诊断书**，七个区块：

```markdown
# 系统诊断书：{系统名称}

## 一、系统边界
一句话陈述范围。

## 二、存量-流量图
```
[流入量] ——→ [ 存  量 ] ——→ [流出量]
```
2-4 组核心存量。

## 三、反馈回路
**调节回路（B）：** ...
**增强回路（R）：** ...

## 四、有限理性与延迟
- 关键角色各自知道什么、做什么决策
- 关键延迟在哪、造成什么后果

## 五、系统陷阱
匹配的陷阱 + 事实依据。

## 六、杠杆点
最高且可行的杠杆 + 干预方向。

## 七、预警与谦逊
系统还会怎么演化？什么条件下分析可能错？
```

最后一个区块不能省。Meadows 的最高教诲是：**模型不等于真相。** 指出假设条件和分析盲区。

## 红线

1. **不出事件清单。** 系统诊断书不是"出了什么事"的列表。至少 80% 内容是结构分析。
2. **不怪人。** 如果分析中出现"都是 A 的问题"——停。把 A 放进系统结构里看：什么结构让 A 只能那么做？
3. **找到延迟。** 没标出至少一个重要的延迟 = 分析漏了系统最反直觉的那一面。
4. **必须标杠杆层级。** 只说"改规则"不够，要注明这是第 5 层杠杆，和它为什么比第 12 层有效。
5. **必须有谦逊区块。** 没有第 7 区块的诊断书 = 你把自己当上帝了。
6. **反翻译腔。** 白话写分析。省"通过""进行""在X层面"。读出声不卡再交付。
